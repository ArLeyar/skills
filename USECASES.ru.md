# Сценарии использования (RU)

Документация проекта — на английском (`README.md` и сами `SKILL.md`). Здесь — практические сценарии: что сказать, что получится, где обычно ломается.

Оба скилла отвечают на один вопрос: **у работы есть финиш?**

| Работа | Скилл | Примитив |
|---|---|---|
| Заканчивается проверяемым состоянием: «тесты зелёные», «миграция прошла» | `goal-prompt` | `/goal` |
| Не заканчивается: следить за CI, за новыми коммитами, за логом | `loop-prompt` | `Monitor`, `/loop`, `loop.md` |

Если задача оказалась не того типа, скилл сам передаёт её второму.

---

## goal-prompt

### 1. Обсудили работу — поставить цель

Самый частый случай. Разобрали в диалоге план, спеку, упавшие тесты, issue. Дальше:

```
/goal-prompt
```

Аргументов не надо: скилл берёт последнюю согласованную, но не сделанную работу из этого же диалога. Он прочитает `package.json` / `Makefile` / `pyproject.toml` (настоящие команды тестов, линта, сборки), `CLAUDE.md`, `git status`, списки разрешений (`ask` / `deny`) и задаст максимум три вопроса — только то, чего в репозитории нет.

На выходе — готовый к вставке блок:

```text
/goal Done when `npm test` prints 0 failures ...
```

Скилл **не запускает** цель. `/goal` — встроенная локальная команда (ставит Stop hook), моделью не вызывается: строку вставляет человек.

### 2. Цель на конкретную работу, без предварительного обсуждения

```
/goal-prompt перевести модуль платежей на новый клиент API
```

Аргумент побеждает контекст диалога.

### 3. Несколько кандидатов в диалоге

Если в разговоре две разные задачи, скилл спросит, какая из них. Склеивать нельзя: одна цель на сессию, а условие про две работы переключится в «выполнено» на половине.

### 4. После прогона — оценить качество

```
/goal-prompt review
```

Один вопрос: работа сделана хорошо / формально условие выполнено, но результат неверный / цель мерила вообще не то. Одна строка дописывается в `~/.claude/goal-quality.jsonl`. Это единственное, чего не пишет ни один лог: машина знает, чем прогон закончился, но не знает, был ли результат годным.

Внутри работающей цели этот режим не вызывать — он задаёт вопрос, а отвечать в автономном прогоне некому.

### 5. Разбор накопленной истории

```
/goal-prompt analyze
```

Читает историю целей самих хостов — SQLite Codex (`~/.codex/goals_1.sqlite`) и транскрипты Claude Code — и соединяет с заметками из `review`. Итог — не отчёт, а конкретные правки в сам `SKILL.md`: если один и тот же сбой встретился трижды, значит чек-лист его пропускает. Меньше трёх прогонов — скилл честно говорит, что данных мало, и останавливается.

### Где цели ломаются чаще всего

- **Доказательство не напечатано.** Проверяющая модель читает ТОЛЬКО транскрипт: команд не запускает, файлов не открывает. «`src/api.ts` меньше 200 строк» проверить нечем, «`wc -l src/api.ts` печатает число меньше 200» — можно.
- **Команда упирается в запрос разрешения.** Автономный прогон замирает на вопросе, отвечать некому. Force-push, `reset --hard`, `clean -f`, запись в Jira — из условия убираются. Rebase не нужен: ветка догоняет main мёрджем и пушится обычно.
- **Классификатор авторежима блокирует и то, чего нет в списках** — `git stash`, `git reflog`, `cd` в чужой worktree. После примерно пяти блокировок подряд агенту гейтится вообще всё, включая `git status`, а повтор заблокированной команды удлиняет серию. Правило в условии: заблокированную команду не повторять и не перефразировать, а останавливать эту линию работы и докладывать.
- **Условие длиннее 4000 символов** — `/goal` отклоняет его целиком, вся выдача впустую. Целиться в 2500–3000 и мерить длину, а не прикидывать на глаз. У Codex такого лимита нет, но одно условие пишется под оба хоста, и ограничения Claude строже.
- **Задача на один-два хода** целью быть не должна: скилл так и скажет, вместо того чтобы выдать условие.

## loop-prompt

Сначала выбирается примитив, потом пишется промпт или скрипт наблюдения, потом скилл сам его взводит (в отличие от `/goal`, который вставляет человек). Если тик умеет пушить, мёрджить, деплоить или писать людям, взвод идёт после подтверждения.

### 1. Реагировать на событие — `Monitor`

```
/loop-prompt следи за новыми коммитами в main и делай ревью
```

Событие само будит сессию: скрипт печатает строку — сессия просыпается. Модель не тратит ход на то, чтобы выяснить, что ничего не изменилось.

Подвохи, которые скилл закрывает сам: в скрипте держится отметка последнего увиденного (иначе один и тот же коммит срабатывает вечно), фильтр ловит ВСЕ конечные состояния (фильтр только на удачный исход промолчит при падении, а тишина выглядит как «всё ещё идёт»), и вместе со взводом сообщается реакция — иначе событие прилетит в сессию, которая уже не помнит, зачем следила.

### 2. Повторяющийся обход без события — `/loop`

```
/loop-prompt разбирать очередь открытых PR
```

Фиксированный интервал (`/loop 15m ...`), когда ритм известен, либо темп по модели (`/loop ...`), когда пауза зависит от увиденного: сборка на подходе — проверить скоро, тихо — реже.

### 3. Один и тот же обход в каждой сессии репозитория — `loop.md`

```
/loop-prompt сделай это дефолтом репозитория
```

Файл `.claude/loop.md`; дальше голый `/loop` запускает именно его.

### Что учитывается в промпте лупа

У `/loop` **нет проверяющей модели**. Промпт срабатывает, ход отрабатывает, ход заканчивается — и промпт срабатывает снова, без изменений. Отсюда всё остальное:

- Промпт идемпотентен. Всё, что небезопасно сделать дважды, несёт внутри проверку «уже сделано?».
- Памяти между тиками нет, кроме транскрипта, а он сжимается. Состояние выводится заново из `git`, `gh`, файла — никогда из «продолжи то, что делал».
- Промпт описывает, как выглядит тик, в котором делать нечего, иначе каждое тихое срабатывание превращается в сочинение.

## Установка

```bash
git clone https://github.com/ArLeyar/goal-prompt.git
mkdir -p ~/.claude/skills
cp -r goal-prompt/skills/goal-prompt goal-prompt/skills/loop-prompt ~/.claude/skills/
```

Вызов — сразу после обсуждения работы: `/goal-prompt` или `/loop-prompt`, без аргументов либо с явной задачей.

Codex: направьте свой каталог скиллов на те же `SKILL.md`. `goal-prompt` пишет условие, годное для обоих хостов. `loop-prompt` — только Claude Code: у его примитивов нет эквивалента в Codex.
